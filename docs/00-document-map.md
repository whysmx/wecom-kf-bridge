## 优先级与变更

用户最新明确要求 > 经评审需求及 ADR > 协议契约 > 架构/数据设计 > 实施任务 > 示例。若两个规范冲突，先写出差异并修订，不得静默采用其中一个。README 是导航，不是省略其他约束的许可。

首版含真实客服账号管理，因此“不要额外后台”应落实为“不做无关运营平台”，而不是不提供管理账号所需界面。本版轻量后台仅服务配置、账号、诊断和审计。

## 证据标签

- **已确认需求**：来自本项目所有者；不是说功能已实现。
- **源码事实**：在固定提交中核对到的行为；必须能定位文件/函数。
- **设计约定**：本网关自行定义的字段、状态和默认值，可经评审变更。
- **待核验**：官方契约、权限或环境尚无足够证据，不得当作测试 oracle。
- **已验证实现**：必须有对应提交、环境、命令及原始报告。

特别区分开发测试 fake 与官方沙箱。本网关的 fake 服务由测试代码控制，不能称为腾讯官方沙箱；录制回包要注明时间、接口和脱敏方式。

## 术语

| 名称 | 定义 |
|---|---|
| 客服账号 | 微信客服中的 `open_kfid`，不是客户本人，也不是企微坐席成员 |
| 客户 | 给客服发消息的个人微信用户，官方标识为 `external_userid` |
| 企业配置 | 网关保存的真实企业和微信客服凭证范围 |
| 绑定 | 一个客服账号与一个 cc-connect 平台实例的对应关系 |
| 兼容企业/应用 | 网关分配给 cc-connect 的虚拟标识，不等同于真实企业应用 |
| 兼容令牌 | 网关颁发给 cc-connect 的 access_token，不是微信官方 access_token |
| 回调校验 Token | 用于签名的约定字符串，不是 `sync_msg` 通知中的拉取 Token |
| 会话代际 | 同一客户在一次 AI 接待期间的路由世代，接管/恢复后可轮换 |
| UNKNOWN | 无法证明外部操作成功或失败，不能等同于失败后自动重试 |

## 最短阅读路径

产品/评审：需求 → 账号管理 → 验收矩阵。后端：AGENTS → 架构 → 两侧契约 → 身份 → 可靠性 → 数据安全。前端：需求 → 账号管理 → 管理 UI/API → 测试。测试：两侧契约 → 可靠性 → 测试 → 验收矩阵。部署：兼容契约 → 运维 → 依据登记。

提交前检查内部相对链接、需求编号、状态名称和示例字段保持一致。所有新增需求必须进入验收矩阵，而不是只写进代码注释。
