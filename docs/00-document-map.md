## 优先级

用户最新要求 > 最新经评审需求/ADR > 对应协议契约 > 架构与实施计划 > 示例。v0.1 中保留的需求、账号行为、身份和测试标准继续有效；v0.2/ADR-0002 对管理实现形态、阶段顺序和证据补充作修订，不删除既有功能。

尤其不能把原管理端点清单理解为必须建设通用 API 平台，也不能把逻辑数据实体理解为必须逐一建表。反过来，“项目小”也不允许略过真实账号 CRUD、鉴权、事务、人工栅栏和 >95% 覆盖率。

原验收矩阵与评审追加矩阵合并使用，状态全部为待执行；没有“文档写了测试”即通过的含义。原模板可简短填写，不是额外项目管理系统。

## 证据等级

- **用户要求/设计约定**：说明产品需要，不是外部 API 事实。
- **固定源码事实**：必须有提交及文件/函数定位；不能外推到全部版本。
- **SDK 注释/项目文档**：可帮助设计和交叉比对，不代表腾讯当前权限或配额。
- **官方/企业核验**：标明适用账号范围、日期、字段与限制；真实效果另附测试记录。
- **已验证实现**：需要实际版本、命令、环境和报告。fake 不是官方沙箱。

## 术语及最短路径

客服账号是 `open_kfid`，客户是 `external_userid`，不是企业员工 userid；昵称只显示。真实微信令牌、兼容令牌、回调签名 Token、通知拉取 token 各自独立。绑定连接一个客服与一个客户端 HTTP 平台实例；代际 UID 防止旧 AI 回复复活，不保证文件权限隔离。UNKNOWN 表示不能证明成功或失败，不等于可安全重试。

评审读需求、评审、ADR-0002；实现读 AGENTS、相关契约、可靠性和对应验收；部署读运维与依据。提交前核对链接、需求/测试编号和完成状态，文档变更记入修改记录。
