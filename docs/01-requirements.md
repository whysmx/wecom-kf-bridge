# 需求规格

> 当前最终设计 · 2026-10-09。实现状态统一为待开发。

## 1. 目标

开发独立项目 WeCom KF Bridge，将个人微信通过企业微信“微信客服”发来的消息转换给现有 cc-connect，再把回答发送回客户。cc-connect 不改源码，不新增平台类型，用户直接在现有 WeChat Work 手动表单和高级选项配置网关。

复用原有项目、会话与 Codex 能力，只用于问答。一个客服账号绑定一个项目，并且必须允许多个客户同时使用同一客服或不同客服进行独立对话。网关采用单进程部署，不限制为单客户，也不能强制所有客户轮流等待整轮 AI 完成。客户、客服和项目数量按配置及实际资源增长，不写死业务数量；网关承担真实客服账号管理与客户昵称透传。

不同客户独立身份和上下文；同一客户在必要环节有序处理。并发、排队、媒体和平台额度有合理上限，实际同时生成容量以 cc-connect/Codex、机器资源与平台约束的联调结果为准，不在文档阶段承诺无限并发。

## 2. 用户与场景

**客户**：从个人微信进入指定客服、发送问题、图片/文件等已支持内容、收到回答，必要时转人工。多个客户可同时发起独立对话；不因另一位客户等待长回答而被网关全局阻塞。客户不需要了解本网关及 cc-connect。

**管理员**：配置真实企业、同步/创建/编辑/删除客服账号、生成接入链接、绑定回调地址、复制 cc-connect 兼容配置、启停 AI 转发、轮换凭证、查看发送失败与人工状态。

**人工客服**：继续使用企业微信原工作台。本网关识别状态并抑制 AI 发送，不另开发坐席聊天界面。

## 3. 需求清单

| 编号 | 必须实现的能力 | 验收要点 |
|---|---|---|
| R-001 | 原有 WeChat Work HTTP 表单接入 | 高级 api_base_url 指向网关；无需改 cc-connect 源码/前端 |
| R-002 | 企业配置与凭证隔离 | 真实微信凭证只留网关；每个绑定的虚拟密钥/令牌互相隔离 |
| R-003 | 微信通知与消息同步 | 验证、解密、分页拉取、持久化、游标与数据原子提交 |
| R-004 | 客服到项目路由 | 一个有效客服映射一个有效平台实例，可服务多客户；未知及冲突映射不猜测 |
| R-005 | 多客户并发、隔离及持续会话 | 单网关进程中不同客户独立并发；慢客户不导致全局 AI 等待；同名不串线，正常代际身份稳定 |
| R-006 | 文本问答及回传 | 兼容 gettoken/message/send/XML 回调；中文、表情和多段回复 |
| R-007 | 客户昵称透传 | 获取客户资料并兼容 user/get；失败回退不阻塞问答 |
| R-008 | 入站媒体及出站图片 | 对齐固定 cc-connect 具备的媒体方向；不虚构其没有的文件发送能力 |
| R-009 | 人工接管与安全恢复 | 接管时抑制 AI；恢复后旧代际回复不可进入新会话 |
| R-010 | 本地可靠性 | 去重、崩溃恢复、有限重试、发送结果 UNKNOWN 可见，不承诺 exactly-once |
| R-011 | 客服账号同步列表 | 分页读取真实可见账号；保留本地绑定；部分失败不得误删 |
| R-012 | 创建真实客服账号 | 名称/头像验证、官方调用、保存 open_kfid、幂等操作记录 |
| R-013 | 编辑真实客服账号 | 修改官方支持的字段，成功后核对；失败不显示虚假成功 |
| R-014 | 删除真实客服账号 | 二次确认、审计、禁止默默批删；与本地停用/解绑严格区分 |
| R-015 | 客服接入链接 | 生成/获取官方支持的客服链接及可选二维码呈现；不是机器人登录码 |
| R-016 | 绑定与兼容配置导出 | 回调可达性验证、生成凭证、字段对照、配置修改审计 |
| R-017 | AI 转发启停 | 仅控制网关转发，不冒充微信账号启停；待处理项有明确处置 |
| R-018 | 轻量中文管理 | 企业、账号、绑定、状态/失败、审计；管理员身份验证和权限保护 |
| R-019 | 安全与隐私 | 密钥保护、SSRF/重放/越权/注入防护、脱敏日志、有限数据保留 |
| R-020 | 可运维部署 | Windows cc-connect 联调；网关服务化、健康检查、备份恢复 |
| R-021 | 测试门禁 | 整体及每个业务模块语句覆盖率 >95%，核心场景全部通过 |
| R-022 | 固定兼容基线 | 核验特定提交和未修改上游版本，升级不得破坏既有配置 |
| R-023 | 配置驱动规模 | 无固定账号/客户数量业务上限；保留分页及资源边界；worker 数不当作客户数上限 |
| R-024 | 只回答部署 | 网关不获取 Codex 写权限；独立校验执行端权限及管理命令 |

## 4. 首版媒体边界

首版目标：文本双向；客户图片、文件及语音数据按 cc-connect 现有 HTTP 适配能力送入；AI 输出图片按现有 ImageSender 接口回传。语音转写由已有 cc-connect 配置处理，网关不新建语音模型。文件解析能力取决于 Agent，收到文件不等于已经能理解任意格式。

出站文件/语音、卡片、群聊、逐字编辑、消息撤回、定时主动营销等不因客服 API 存在就自动纳入。遇到不支持类型，应记录并给管理员明确能力状态，不能悄悄伪装成文本或丢弃。微信官方限制及媒体字段仍须完成外部契约核验。

## 5. 非目标

不改 cc-connect；不使用智能机器人 WebSocket 协议；不通过真实机器人或自建应用中转同一消息；不调用模型；不开发客服坐席工作台、计费、客户营销、复杂多租户、知识库、代码执行平台；不声称支持任意第三方企微客户端。

不承诺无限并发、昵称即时更新、自动终止正在运行的 Codex、所有消息恰好处理一次、所有断线消息都能重新触发客户端、或已经调用接口的消息能被撤回。具体边界见可靠性文档。

## 6. 实现基线与待核验项

单企业、单实例、单网关进程，支持进程内多客户并发；推荐 Go/SQLite/内嵌中文管理页，这是实现建议而非用户指定语言。按照[架构决策](adr/0001-design-baseline.md)在首次实现固定工具版本。网络与安全默认值是产品保护值，不是微信配额。所有数据与令牌按企业/绑定范围组织，不新增租户运营平台。

客服账号真实权限、发送窗口/频率、客户资料可见性、媒体限制、会话状态值及转换条件须记录到外部核验表。未经验证不可用“默认 5 个账号”“48 小时”“随时主动发消息”等记忆代替真实合同。单进程的并发设计也不能代替执行端实际容量测试。

## 7. 完成定义

所有 R-001～R-024 有测试证据；首版功能完整；外部核验闭环；未修改 cc-connect 实机链路及多客户并发 AT-070 通过；覆盖率实际 >95%；无未处置的安全阻塞；交付部署、恢复、版本兼容及风险说明。文档提交本身不满足产品完成定义。
