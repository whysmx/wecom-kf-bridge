# 微信客服侧适配契约与核验清单

> v0.1。本文将产品需要与外部接口事实分开。本次未能读取微信客服官方页面正文；下列候选路径、字段、权限和状态值必须在 P0 用官方资料及真实测试账号核验后冻结，不得当作已验证的最新 API 规范。

## 1. 资料入口与边界

用户明确指定：[95166：客户基础信息](https://kf.weixin.qq.com/api/doc/path/95166)。该能力用于客户昵称等资料，不代替客服账号管理。官方入口：[微信客服 API 文档](https://kf.weixin.qq.com/api/doc/)、[企业微信开发文档](https://developer.work.weixin.qq.com/document/)。具体核验状态登记于 [依据文档](14-sources-and-verification.md)。

网关向官方 API 使用真实企业对应的有效凭证和令牌；兼容 cc-connect 的虚拟 corp_id/secret/token 不能发送到官方。只支持管理员授权的企业及客服账号，不实现第三方应用套件/OAuth 运营平台。真实凭证属于微信客服专用 Secret 还是已授权自建应用，必须根据该企业实际接入方式核实，不要求用户把真实 Secret 贴进仓库。

## 2. 产品所需外部操作

下表为实现核验清单。方法/路径是待验证的预期接口标识，P0 必须补官方证据、请求/响应必填字段、限制及脱敏夹具，任何不符先改契约再编码。

| 能力 | 待核验方法与路径 | 对应需求 |
|---|---|---|
| 获取真实令牌 | GET /cgi-bin/gettoken | R-002 |
| 拉取客户消息与事件 | POST /cgi-bin/kf/sync_msg | R-003 |
| 发送客服消息 | POST /cgi-bin/kf/send_msg | R-006/R-008 |
| 客户基础信息 | POST /cgi-bin/kf/customer/batchget | R-007；95166 |
| 添加客服账号 | POST /cgi-bin/kf/account/add | R-012 |
| 编辑客服账号 | POST /cgi-bin/kf/account/update | R-013 |
| 删除客服账号 | POST /cgi-bin/kf/account/del | R-014 |
| 客服账号列表 | POST /cgi-bin/kf/account/list | R-011 |
| 客服接入方式/链接 | POST /cgi-bin/kf/add_contact_way | R-015 |
| 接待状态读取 | POST /cgi-bin/kf/service_state/get | R-009 |
| 接待状态转换 | POST /cgi-bin/kf/service_state/trans | R-009 |
| 接待人员列表 | POST /cgi-bin/kf/servicer/list | R-009/R-018 的可选接管目标验证 |
| 临时媒体上传/下载 | POST /cgi-bin/media/upload；GET /cgi-bin/media/get | R-008/R-012/R-013 |

不假定列表接口一定用 GET；不把普通 `/cgi-bin/message/send` 当成客服发送；不把企业员工 userid 当作客户 external_userid。`send_msg_on_event` 等欢迎语专用接口不属于首版必需范围，不能用它绕过发送额度。

## 3. 回调接收

本网关公开路线约定为 `/webhooks/wechat-kf/{tenant_key}`，此路径是网关设计，不是微信强制路径。GET 用于验证、POST 用于通知；签名参数、加密内容和接收方标识以官方规范为准。

处理顺序：请求大小/方法校验 → 按已配置企业定位真实回调密钥 → 校验签名/解密/接收方 → 解析合法事件 → 持久化同步任务及必要拉取材料 → 尽快回复官方要求的成功体。不得等待 Codex 或同步拉完全部分页才回复。

回调通知通常不等于客户正文。`Token` 的作用、有效期、与 `OpenKfId` 的对应和事件类型必须核实；它与 access_token、回调签名 Token 是三个概念。禁止将通知原文直接作为用户问题。

安全校验失败不入库执行。重复通知可以合并同步任务，但不能仅以通知次数推断消息条数。允许保存加密/受保护的短期拉取材料；日志不得显示 Token。官方重试与允许时间偏差需核验，不能随意选择过短重放窗口导致合法重投失败。

## 4. sync_msg 与游标

需要核验的字段包括 cursor、token、limit、open_kfid、next_cursor、has_more、msg_list；允许类型和必填条件以官方为准。特别要核实游标作用域究竟按企业/应用/客服账号哪种组合划分。最终用 `sync_scope_key` 明确表示；不能在未验证时假定每个 open_kfid 都可独立推进同一来源游标。

对同一 scope 串行拉取。一页数据的消息/事件持久化和 next_cursor 更新必须同事务；事务失败不得前进游标。只有 has_more 表示继续才翻页，并防御无进展的循环、重复页、空页及异常游标。游标过期/权限改变时暂停并提示修复，不能自动重置为空吞掉或重放大量消息。

保留原始 origin、msgtype、send_time/事件时间及消息 ID。建立明确分类表：客户问题可转发；人工/机器人发送、接待状态、系统通知不能当客户问题再次触发。未知枚举持久化为不支持并告警，不默认当客户文本。

## 5. send_msg

核验 touser、open_kfid、msgtype、内容、可选客户端 msgid、返回 msgid 和错误码语义；特别检查是否提供真正可用于重试的幂等/去重承诺，而不只是在请求中存在同名字段。

每次发送必须校验真实企业/客服权限、网关 binding 与客户 UID 的关联、人工状态和发送窗口。令牌获取失败、频控、权限拒绝、永久参数错误、超时未知分别分类。仅对确认没有副作用的失败执行自动重试；网络断开后“可能已发出”不能盲目重试。

文本长度、字符/字节单位、窗口、每会话额度、媒体大小、链接能力等由已核验的 policy 配置表达。文档中的内部缓存时间、队列大小不是腾讯配额。不要把其他 API 或社区代码中的数字复制成常量。

## 6. 账号与客户资料

账号创建/更新预期涉及 name、头像 media_id，返回 open_kfid；删除与列表可能对权限范围有不同约束。P0 核验可创建数量、名称长度、头像类型、分页和权限。产品不自己固定数量上限，平台限制要如实显示。

客户资料查询预期以 external_userid 列表取得 nickname、avatar 等字段；是否含 gender、unionid、授权范围和可查询时效必须核实。产品只依赖可用昵称；不以可能存在的敏感字段增加身份收集。批量部分失败应逐客户处理；不能用第一位客户的资料填全部记录。

## 7. 人工状态

先核实官方数字状态与合法转换图，再映射为本网关 AI_ELIGIBLE、WAITING_HUMAN、HUMAN、CLOSED、UNKNOWN。数字映射只放一处，不能将旧资料里的枚举散落在业务代码里。

默认发送前向官方核实当前状态，无法确认则暂停 AI 发送。网关自己的停用状态不能冒充微信官方状态。人工工作台变化可能先于回调到达，因此需状态核查；仍无法原子阻止已经提交到官方的在途请求，此边界必须说明。

## 8. 每个外部接口的冻结交付

实现前必须具备：官方标题/链接/核验日期、凭证与权限、方法/路径/字段及枚举、成功/失败/部分失败脱敏样本、分页与幂等说明、约束及可恢复性、对应测试编号、测试企业/环境标识（不含密钥）。官方内容不可访问时登记阻塞，不伪造 OpenAPI 或通过测试。

允许先完成对确定内部契约的 fake 和状态机测试；外部接口相关功能不能在没有官方核验与联调的情况下标为可发布。
