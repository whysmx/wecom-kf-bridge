# 技术可行性评审与最小修订

> v0.2 · 2026-10-09。评审对象是设计文档，不是已经运行的网关。结论基于固定源码检查；未运行 cc-connect、Codex 或真实微信接口。

## 1. 结论

**主路线有源码支持，适合按小项目实施；目前不能宣称已实现、已稳定运行或已完成官方联调。** 保留微信客服 → 独立网关 → 未修改的 cc-connect WeCom HTTP 适配器 → Codex。上游也支持 `api_base_url`，并非只能依赖用户 Fork。网关必须同时实现兼容 API 和反向加密 XML 回调，不是修改一个 URL 的透明代理。

实现规模控制为：单实例、单进程、SQLite、少量有界后台任务、同进程中文管理页。首版按单企业部署，不建设租户运营系统。真实客服账号管理、昵称、人工接管、媒体目标、身份隔离及原有 >95% 测试要求不删减；分阶段开发不等于降低完整首版验收标准。[ADR-0002](adr/0002-small-project-baseline.md)规定简化范围。

## 3. 发现及处理

| 编号 | 发现与影响 | 最小处理 |
|---|---|---|
| F-01 | 原文档把接待人员列表写成 POST；WxJava 实现使用 GET | 更正为 GET `/cgi-bin/kf/servicer/list`，用查询参数传 `open_kfid`；真实权限仍需联调 |
| F-02 | HTTP 回调先写 200，再解析/过滤/调用 handler；200 不能证明已触发 AI | 只记录 HTTP_ACCEPTED；不得凭 200 标已回答，也不得因没有回复盲目重投 |
| F-03 | `IsOldMessage` 比较的是进程启动时间减 2 秒，不是当前时间减 2 秒 | 保留原始 CreateTime；重启前历史消息默认暂停，由客户重新提问；不知道客户端启动时间时不伪造“已过期”的确定判断 |
| F-04 | 客户端 MsgId 去重仅在进程内保留约 60 秒，重启即丢失 | 网关持久化去重；投递结果未知默认不自动重试，不能把 60 秒当跨重启可靠窗口 |
| F-05 | `Reply` 每 2000 UTF-8 字节分块；默认思考/工具提示也可能发送消息 | 关闭非必要提示；逐条计入保守发送预算；不假定每个问题只有一个发送请求、不自动合并、不静默截断 |
| F-06 | SDK 注释记录 48 小时及最多 5 条发送限制；不是“每次 AI 回答可发 5 条” | 在真实企业核验并冻结 policy；测试多分段、图片和提示共用额度；已发送成功部分不能回滚 |
| F-07 | 官方发送请求可含 msgid，但所读实现没有证明重试幂等；sync 不返回 API 发出的成功消息 | UNKNOWN 不盲重发，也不承诺通过 sync_msg 自动对账所有发送；后续失败事件单独登记 |
| F-08 | 人工接管后旧结果可能迟到；仅查询当前状态不能发现遗漏的完整人工接管/结束过程 | 持久化人工暂停及代际；事件缺口时暂停恢复，明确新代际；保留已经在途请求的竞态边界 |
| F-09 | `admin_from` 仅拦部分特权命令；上游测试明确部分 `/cron`、`/commands` 操作不要求管理员 | 客户入口禁用控制命令和别名路径；客户端项目级禁用相关命令并回归；人工/新会话等动作在网关处理，不拼命令投递 |
| F-10 | Codex 只读不等于不能运行读取命令，也不等于客户间文件权限隔离 | 使用 exec + suggest、独立低权限服务账户、只读公共资料和受保护运行目录；未经隔离验证不接入跨客户敏感文件 |
| F-11 | 稳定 UID 不阻止 cc-connect 自身闲置重置；配置示例未设置时默认 30 分钟 | 连续问答部署显式 `reset_on_idle_mins=0`，或明确告知闲置重置；不把自动新会话误判为路由故障 |
| F-12 | 图片入站固定标记 image/jpeg；媒体下载只读响应体，不校验 HTTP 状态 | 投递前取好并固定媒体，图片转为受控 JPEG 或验证真实解码链；非 200 空响应只能避免泄密，不能保证客户端不生成空附件 |
| F-13 | 原设计把人工接管放到较晚阶段；管理 API、操作编排和逻辑数据实体易被实现成通用平台 | 人工暂停、命令限制、持久化先于对外文本试用；管理优先同步表单，小量数据库状态，不建分布式租约/通用任务框架 |

F-02～F-12 中涉及权限、错发或丢失的场景均是发布检查项，不是可以因为项目小而略过的优化。

## 4. 能力判断与剩余限制

文本双向、客户标识映射、昵称查询兼容、真实账号 CRUD/链接均有对应接口或源码路径，未发现需要修改 cc-connect 才能实现的结构性障碍。人工接管可以做发送抑制，但不能无改客户端取消已运行的 Codex，也不能撤销已经提交到微信的消息。代际切换会新建客户端上下文。

持久化保证的是网关内部消息和游标的一致性，不是端到端 exactly-once。未知发送结果、回调接受后客户端崩溃、重启历史过滤、媒体下载异常和平台限制必须作为可见状态处理。昵称缓存更新不等于 cc-connect 界面即时更新；UID 区分会话不等于操作系统区分文件访问权限。

语音/文件/图片按两侧实际能力交集逐项上线。没有经过异常路径与真实解码验证的媒体类型保持关闭，并明确标为未完成；不能因此宣称 R-008 已验收。
