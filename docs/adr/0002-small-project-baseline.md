# ADR-0002：小项目的最小可靠实现

- 日期：2026-10-09
- 状态：依据项目所有者本次“不要过度设计，直接修订文档”的授权采用。
- 关联：[评审](../15-feasibility-review.md)、[ADR-0001](0001-design-baseline.md)。

## 决策

沿用独立网关和未修改 cc-connect HTTP 路线。建议 Go + SQLite + 内嵌 HTML；语言建议不是已选定工具链，实际版本和必要驱动在首次实现时一次性记录。先验证最小文本链路，不为选技术或搭框架延后协议验证。

首版单企业、单实例、单进程，数据保留企业范围但不实现租户注册、租户切换平台或复杂 RBAC。账号/客户/绑定数不硬编码；并发、排队、媒体和磁盘仍需有界。未知账号不进入默认项目。

中文管理优先服务端渲染页面与少量表单处理器，保留真实客服同步、创建、编辑、删除、链接、绑定及诊断。读取均鉴权，修改具备 CSRF、对象校验、revision 和防重复提交，删除另做明确二次确认。无需先交付通用公共 REST API、独立 SPA、统一异步操作编排或多级管理令牌体系。

管理写入在有界请求中同步执行，保留操作记录用于崩溃和 UNKNOWN 核查；只有确实不能及时完成的同步任务才后台处理。不能先显示成功再异步调用官方。回调同步、投递等少量任务可由数据库状态加同进程 worker 完成，不引入 Redis、消息队列、分布式锁、抢占租约或通用调度平台。

数据文档中的对象是逻辑职责，不要求一个职责一张表、一个表一个包。可合并 token/凭证、同步任务/游标、单次尝试摘要等存储，只要事务、唯一键、不可重用 UID、未知状态、审计和恢复测试不丢失。也不为了少一张表把所有状态塞入无法约束的 JSON。

人工暂停/代际、只读与命令权限、可靠收发是第一条对外文本链路的组成部分，不推迟到媒体或 UI 完工后。默认由一个实现者顺序完成可验收小步，不要求四个 Agent 或多个并行分支。

## 不简化的内容

原 R-001～R-024 保留。客服账号真实 CRUD、昵称、原有媒体目标、人工接管和安全不能替换成仅本地配置。整体、每业务模块及原约定的其他覆盖口径仍须严格 >95%；关键场景全通过。可用小脚本实现门禁，不先建设通用测试平台，也不删除测试以降低工作量。

来源按“源码事实、SDK 注释、官方/企业实测”分级。可按当前能力切片核验并推进内部开发，不必等待全部外部资料齐全才写任何测试；相应真实功能发布前仍须确认其权限与契约。源码审查不等于真实接口测试。

## 取舍

保留 UNKNOWN，不提供无法实现的 exactly-once。重启历史消息不保证补答；人工恢复新建上下文；共享 OS 账户不是客户文件安全边界。文档和管理界面均需说明这些限制。

本 ADR 替代 v0.1 中把管理 API 形态、异步 202 流程、物理表拆分、多 Agent 分工或全量预先冻结理解为强制框架的要求；不覆盖其业务、安全和质量不变量。以后只有实际瓶颈或明确新需求才考虑扩容及新增组件。
