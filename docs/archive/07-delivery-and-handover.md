# 消息可靠性与人工接管

> v0.2。目标是单实例可恢复、失败可见、不盲目重复执行；不承诺端到端 exactly-once。

## 1. 不变量

未验证通知不执行业务；一页消息与游标同事务；同一官方消息只产生一个正常 Inbox；兼容 MsgId 持久化唯一。发送必须同时通过真实权限、active binding/revision、客户 UID/generation、人工状态及发送窗口/预算。未知结果不当作尚未发生。

HTTP_ACCEPTED、UPSTREAM_ACCEPTED 和客户已读是不同概念；本项目不能证明最后一种。与客户端及官方交互的确切限制见[兼容契约](03-cc-connect-contract.md)、[微信契约](04-wechat-kf-contract.md)。

## 2. 拉取和最小任务机制

回调验签解密成功后短事务保存待同步标记及有效拉取材料，随后响应。一个同进程 worker 按固定 scope 推进游标；可重复唤醒，消息用唯一键去重。网络调用不跨 DB 写事务。

拉取页 → 校验边界/字段 → 事务写 Inbox、事件和 next_cursor → 按 has_more 继续。空页不等于结束；重复页、未知类型、无进展需专门处理。无法分类的完整事件可隔离并保留记录，不因一条未知类型永远卡住游标。

通知 token 会失效；只有确认其有效期及无 token 限频规则后才开启重启补偿拉取。失效游标/权限变化暂停并诊断，不清空游标猜测恢复。持久化恢复不代表能突破官方可拉取时间范围。

单实例启动互斥，SQLite 状态是恢复源，内存队列只作通知。无须设计跨进程租约、分布式锁或单独消息队列。进程崩溃后按数据库记录判定任务，而不是把所有处理中状态重置成待重试。

## 3. 入站投递

```text
RECEIVED → CLASSIFIED → READY → POSTING → HTTP_ACCEPTED
               │          │       ├→ RETRY_WAIT（确定未投递）
               │          │       └→ DELIVERY_UNKNOWN
               │          ├→ HELD（人工/停用/待核验）
               │          └→ EXPIRED（有确定依据）
               └→ IGNORED / UNSUPPORTED
```

连接拒绝等确定没有投递的失败可以有限退避重试；发送后断线、目标提前 200 后崩溃等无法证明业务结果。收到 200 仅记 HTTP_ACCEPTED，不虚构“已回答”。缺少回复本身不是可安全重试的证明。

**DELIVERY_UNKNOWN 默认不自动重试。** 客户端约 60 秒去重是进程内缓存，重启即消失；不能以仍在 60 秒内为由宣称安全重投。确需人工重试应显示重复风险，沿用原 MsgId 和时间，不改正文/身份以逃避去重。

旧消息规则是原 send_time 早于客户端本次 StartTime 减 2 秒，不是当前时间减 2 秒。挑战 GET 不提供客户端启动时间。已知客户端重启后历史记录默认 HELD；管理员核查或由客户重新发送问题。不知道是否重启/是否过滤时保持可解释的不确定状态，不伪标 EXPIRED。

网关自己的重启不等于客户端重启。确定未发送、目标仍是同一次进程且授权/窗口有效的任务可继续；不能统一丢弃全部恢复消息。恢复窗口的判定依据要记录，无法确认时暂停。禁止把 CreateTime 改成当前时间或 0。

同客户按收到的有序记录投递，媒体预取就绪后再发 XML。客户端内部异步处理，网关没有每轮完成回执，因此不承诺 AI 严格按问题逐条完成或逐问题关联答案。排队容量有界，不靠生成中的“忙”标志无限积压。

## 4. 出站发送与预算

```text
CREATED → VALIDATED → SENDING → UPSTREAM_ACCEPTED → DELIVERY_FAILED（后续失败事件）
              │         ├→ UNKNOWN
              │         └→ REJECTED
              └→ BLOCKED
```

每次兼容发送先持久化 outbox、绑定/客户/代际、内容受保护引用及版本快照，再发送。一次请求的鉴权、官方状态查询、令牌和发送使用一个总截止时间，建议 15 秒，小于客户端 30 秒 HTTP timeout；不持数据库写事务等网络。

明确官方接受才回 `errcode:0`。明确拒绝回非零；可能执行但响应丢失回 70008/UNKNOWN。请求取消不删除记录，已经在途的同一次请求后来得到确定结果可以更新状态，但不能假装客户端收到了晚到的成功响应。**返回失败后不另起后台任务重新发送。** 确定未执行的短重试只能在本次预算内完成，超过预算交由可见失败/人工处置。

没有客户端幂等请求键，也没有完整回答边界。相同内容可以是合法新回答，不按内容哈希/N 秒窗口吞消息。官方可选 msgid 不等于已证实的去重承诺；同一 outbox 尝试保留稳定内部标识，但 UNKNOWN 默认不重发。

按已核验 policy 保存客户最近有效主动消息、窗口与本地保守计数。重复/旧客户消息不能反复刷新预算；并发发送先原子预留容量。成功及 UNKNOWN 都保守占用额度，只有有明确依据才释放。所有分段、图片、提示共用预算，不能按每个 HTTP 请求各给一份新额度。

客户端 2000 字节分段，关闭思考/工具提示也不保证只有一个发送请求。超限、窗口关闭或某段失败时停止继续发送，保留已成功及未发送记录，界面显示部分发送；不能静默截断、自动合并、换客服或窗口以后主动补发。向客户解释失败的提示本身也须满足状态/预算，没有额度时只在管理员诊断显示。

官方接受不代表客户已收到；出现匹配的后续失败事件可更新 DELIVERY_FAILED。SDK 说明 sync_msg 不返回 API 发出的成功消息，因而“同步没看到”既不是未发送证据，也不能清除 UNKNOWN。无法关联的失败事件保留待核查，不冒充新客户问题。

## 5. 人工暂停与恢复

内部状态 AI_ELIGIBLE、WAITING_HUMAN、HUMAN、CLOSED、UNKNOWN；数字映射与合法转换只放微信适配层，在实际企业核验后固定。unknown/查询失败默认不发。

客户的转人工意图按明确网关入口规则处理，或管理员显式操作：先持久化本地发送栅栏、封锁当前 UID，再请求官方转换。官方失败仍保持暂停并显示结果，不自动恢复 AI。不能伪造 `/stop` 等客户命令去取消 Codex。

企微工作台接管通过状态事件同步，并在发送前再次查询当前状态。**当前状态为 AI 不能证明此前没有发生过人工接管又结束**：如果相关事件全部晚到或丢失，仅检查当前值仍有风险。处理已收到的历史人工事件并保持人工暂停锁；检测到同步中断、游标缺口、未知状态或恢复旧备份时进入待核查，不自动恢复旧 UID。

恢复由管理员或经过验证的明确规则确认：当前官方状态允许、可用状态事件已处理、旧代际已封锁，再创建新 UID/generation。无法证明事件连续性时保持暂停，由管理员核查后以新代际恢复。旧 UID 及 outbox 永不重新放行；正常对话不每消息换代际。恢复会新建 cc-connect 上下文，默认不补送人工/停用期间历史问题。

没有办法靠这套 HTTP 协议完全发现所有未观测到的外部瞬时变化。本项目用事件、前置查询和保守暂停降低风险，不声称“任何时刻绝对零抢答”。

## 6. 竞态、重试与停机

同会话通过短临界区/版本复查串行裁决发送资格与本地栅栏；跨网络不持 DB 锁。定义清楚 SENDING/已在途的边界：栅栏建立后新的发送资格必须拒绝；已获准且进入外部请求的操作可能完成，记录 in_flight_at_handover，无法保证撤回。即便在请求前再查状态，跨系统仍不是原子事务。

| 失败类型 | 处理 |
|---|---|
| 明确请求未执行的 Token 失效 | 合并刷新，在本次预算内最多一次重试 |
| 只读接口暂时失败/确定连接未建立 | 有界退避，保留顺序与总时限 |
| 限流 | 尊重官方约束；不能无限重试或换身份绕过 |
| 无权限、参数错、超窗、旧 UID、人工 | 拒绝/暂停，不自动重发 |
| 有副作用的响应丢失 | UNKNOWN，保留证据与人工核查 |
| 数据库满/损坏、无法持久化 | 不再承诺接受新任务，报告不健康 |

停机停止领取任务并等待有限在途操作；崩溃遗留 POSTING/SENDING 先置待判定，成功记录不重发。恢复旧备份默认维护模式，先核查外部已完成操作和人工状态，不能从旧游标重放所有内容。后台账号创建/删除也遵守未知结果不盲重试，但不建设统一分布式事务框架。

## 7. 诊断与验收

记录 trace/inbox/outbox/operation、绑定 revision、代际、错误类别、时间和必要脱敏外部标识；正文/密钥不进日志，指标不使用无限客户维度。管理员看得见 HELD、UNKNOWN、部分发送和后续失败，不把存活检查当消息成功率。

原 AT-016～AT-029、AT-048～AT-050 与新增 AT-060～AT-063、AT-067 均须故障注入：事务前后崩溃、两侧各自重启、重复通知/分页、写请求响应丢失、额度不足、人工完整周期事件延迟、旧代际迟到、备份回滚及磁盘故障。每项同时断言状态和不应发生的外部副作用；当前均未执行。
