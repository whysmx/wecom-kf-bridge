# 测试策略与 >95% 覆盖率门禁

> v0.1。以下是实现后的强制验收标准，不是当前测试结果。本仓库当前只有文档，覆盖率为“未测/不适用”，不能显示 100% 或绿色达标徽章。

## 1. 指标定义

用户要求测试覆盖率在 95% 以上。本项目采用可自动检查的严格口径：

| 范围 | 门槛 |
|---|---|
| 所有手写服务端生产代码总体 | 自动化语句覆盖率严格 >95% |
| 每个业务模块 | 分别严格 >95%，不得靠其他模块稀释 |
| 新增/修改的可执行语句 | 严格 >95%；无可执行语句时标 N/A |
| 安全/隔离/事务/接管关键场景 | 本文及验收矩阵列出的分支场景 100% 通过 |
| 自行编写前端业务脚本（若采用） | 语句、行、函数、分支分别 >95% |

Go 原生 coverage 是语句覆盖，不等同于分支覆盖；不能把 `go test -cover` 的结果写成 Go 分支覆盖 95%。状态转换、授权分支、负向路径另用显式用例验证。参考 [Go 测试命令](https://pkg.go.dev/cmd/go#hdr-Test_packages) 与 [覆盖率报告](https://go.dev/doc/build-cover)。

精确判定：设覆盖语句 C、总语句 T，T 必须大于 0 且 `100*C > 95*T`；恰好 95% 不通过，不能按显示四舍五入决定。示例：950/1000 失败，951/1000 通过。模块百分比不得取简单算术平均，必须按原始语句数加权。

## 2. 分母不能被缩小

计入所有手写业务代码：HTTP handlers、验证/鉴权、加解密封装、微信连接器、数据库操作/迁移逻辑、状态机、后台业务、配置、生命周期/关闭逻辑、错误处理及自写前端逻辑。Go main 中的业务初始化不能整包排除，应拆成可测试入口并通过进程测试覆盖。

允许不计入：第三方依赖/标准库、经声明且未手改的生成文件、纯静态资源、测试代码。纯 HTML/CSS 不算代码覆盖，但须做页面流程测试。任意覆盖率排除项必须在报告公开，变更需所有者审核；不得排除本项目业务分支。

缺少测试的生产包必须以零覆盖计入，不能因为没有测试文件就从清单中消失。P1 增加一个“无测试生产包”验证夹具证明门禁会下降/失败。Windows 特有代码需 Windows 原生测试，不能用 Linux 无法编译到它作为排除理由。

## 3. 业务模块边界

覆盖率报告至少单列：兼容 HTTP/XML、微信 API/回调、客服账号/绑定、客户身份/昵称、消息/接管、媒体、管理 API/页面业务、安全、配置/持久化/运行生命周期。P0 以路径映射固定清单。

模块重构后更新映射及历史对照，不能为了掩盖低覆盖合并进高覆盖包。代码行计数变化大且测试不变时必须审查。

## 4. 测试层级

**单元测试**：输入校验、JSON/XML 转换、状态迁移、权限矩阵、时间边界、错误分类、分页、补位和签名、去重键、UID、昵称缓存、分块。时钟/随机源/网络/睡眠注入，不靠长 sleep 或真实微信服务。

**集成测试**：实际 HTTP 服务+真实临时数据库+真实事务/迁移+临时文件；fake 只放官方网络及外部执行边界。覆盖数据库失败、进程退出、重启、租约/游标、缓存并发、请求截止。

**客户端契约测试**：对固定 cc-connect 提交的未改源码适配器运行交互。可在独立测试 harness 引用其导出 Platform 接口，以测试 handler 捕获 Message；不得 patch 其协议代码。验证 GET challenge、加密 XML、UserName、入站媒体、Reply/SendImage 及真实出站请求。不允许只用自己写的 fake cc-connect 证明兼容。

**全链路测试**：未修改的 cc-connect 二进制+网关+真实测试微信客服+按只读权限运行的 Codex，验证现有网页表单配置。真实 API 联调是发布门禁，不在普通 PR 自动调用真实账号删除/发送接口。适配器 harness 测试不能冒充完整二进制/GUI E2E。

**安全/故障测试**：异常签名、SSRF、跨账号、XSS、磁盘满、超时未知、部分成功和接管竞态。每个测试除了预期结果，还需断言不得产生的外部副作用。

## 5. 强制场景组

| 组 | 必测内容 |
|---|---|
| CRYPTO | 43 字符 key、Unicode 字节长、32 分组补位、错误 key/签名/receiver、截断、恶意长度、独立黄金向量 |
| AUTH | 虚拟/官方 token 混用、跨企业/绑定、过期/撤销、刷新并发、未知用户、群发拒绝 |
| SYNC | 多页/重复页/空页/无进展、部分失败、游标事务前后崩溃、未知 origin/type、合法重复通知 |
| ROUTE | 同名不同客户、同客户多客服、重复 active binding、旧 revision、端口冲突、改绑/解绑 |
| NICK | 批量部分失败、空昵称、表情/恶意字符、缓存 hit/miss/过期、客户端非空 name 缓存行为 |
| SEND | 中文分段、合法相同内容、HTTP 200+非零 errcode、限流、确认失败、响应丢失 UNKNOWN、部分分段发送 |
| HANDOVER | 接管前/生成中/发送前/在途/恢复后，旧代际拒绝、官方状态查询失败、非原子窗口标注 |
| ACCOUNT | 真正 CRUD 契约、重复提交、同名不同账号、外部成功本地失败、列表不可见、删除二次确认与 UNKNOWN |
| MEDIA | image/voice/file 入站、image 出站、过期/跨绑定/过大/错误类型/伪路径、失败不把 JSON 当文件 |
| ADMIN | CSRF、权限、并发 revision、停用与删除区分、操作状态、配置导出和密钥脱敏 |
| OPS | Windows 运行/重启、迁移/恢复/磁盘满、终止任务恢复、日志保留/敏感数据、健康状态 |

详见 [验收矩阵](13-acceptance-matrix.md)，场景名称与编号需写进测试名或测试元数据。

## 6. 工具与门禁流程

若 P0 接受 Go 基线，以下是未来 CI 应执行的示例命令；当前没有 go.mod，不能在文档阶段冒充已执行：

```sh
go test ./... -count=1 -covermode=atomic -coverpkg=./... -coverprofile=coverage.out
go tool cover -func=coverage.out
go tool cover -html=coverage.out -o coverage.html
go vet ./...
go test ./... -race -count=1
```

race 必须在支持该工具链的 runner 原生执行，具体平台/CGO 条件 P0 固定。Windows 与 Linux 分别有测试记录，不以交叉编译代替 Windows 运行。coverage.out 只覆盖到被正确插桩的代码；P1 的门禁工具必须核对生产包清单与缺失包，不只解析屏幕上的 total。

主门禁使用一次可重复的全量自动测试覆盖率统计。需要单独进程的集成覆盖可使用 Go 官方 GOCOVERDIR/covdata 机制；不同报告只能对相同源码块去重合并，不能相加百分比或重复累加分母。原始单元/集成报告分别保留，跨 OS 统计说明各自文件范围。优先让每个支持 OS 的本地生产代码范围独立 >95%。

差异覆盖率按 PR base/head 的可执行语句映射，无法映射时退回修改文件完整覆盖检查，不能跳过。文档/静态文件变动显示 N/A，不记 100%。

CI 要实现以下顺序：格式/静态检查 → 包清单/生成物核查 → 单元/集成/契约 → 原始覆盖率 → 模块及 diff 门禁 → 前端业务检查（有则执行）→ 安全/依赖检查 → 上传报告。失败不得使用 `continue-on-error`、吞 exit code 或自动关闭测试。

## 7. 覆盖率检查器自身测试

必须用夹具验证：94.99、95.00、95.01 边界；总语句为 0；报告不存在/损坏；未统计生产包；重复 profile 块；含冒号的路径；模块清单遗漏；排除规则扩张；源 SHA 与报告 SHA 不同；失败测试仍生成报告。任一异常默认门禁失败。

覆盖率高但没有行为断言仍可能测试无效：安全/路由/状态核心函数需引入人工缺陷或受控 mutation 检查，证明测试能检测关键条件反转。无需首版建立庞大 mutation 平台，但报告应有至少一组代表性缺陷被捕获的证据。

## 8. 数据与真实账号隔离

默认测试不访问外网。官方 fake 使用经核验的脱敏合同夹具，明确标记不是官方沙箱。测试 ID、昵称、媒体全部为合成数据。CI 不依赖真实 Secret；受控 E2E 使用独立测试企业/账号及最小权限，破坏性用例必须显式授权和清理记录。

不做“临时允许生产删除来验证覆盖率”；也不复制客户真实对话到 fixture。网络录制样本保留结构与错误类型，不留可追踪个人的字段。

## 9. 发布门禁及报告

全量测试、关键矩阵、安全检查、Windows E2E、真实微信管理/消息联调、>95% 原始证据全部齐全才可发布。官方页面不可读、权限未获确认或某条关键用例未测时对应状态为 blocked，不得勾选。

[测试报告模板](templates/test-report.md) 须写运行日期、网关/cc-connect SHA、Go/OS/浏览器版本、命令、用例数、原始 C/T、各模块/diff/前端结果、失败/未执行项、排除清单、证据链接和限制。覆盖率门禁“在文档中规定”与“已经由 GitHub CI 强制执行”必须分开陈述。
